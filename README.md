# QRFerry

نقل الملفات عبر بثّ QR متحرك أو اتصال WebRTC مباشر بين جهازين.

**React 19 + Vite + Capacitor 8**، بواجهة Mulberry ومكونات Glisse الأصلية. لا يوجد خادم Next.js أو تحميل موقع بعيد داخل APK.

## طرق النقل

- **Send → Scan:** نقل بصري دون شبكة. التصحيح RaptorQ، وفك QR بواسطة ZXing، داخل Web Worker. تنتقل ملكية مصفوفات الصور والملفات بـTransferable ArrayBuffer؛ تحديثات معلومات الماسح 8 مرات/ثانية.
- **Pair / Chat:** ربط موثق بـQFB1 و128-bit secret، ومحادثة وملفات عبر WebRTC/DTLS. خادم الإشارة لا يحمل بايتات الملفات. وجود شبكة للجهاز لا يثبت مشاركة Wi-Fi أو إمكانية الوصول إلى الطرف الآخر.
- **Quick transfer → `/tv`:** مستقبل الشاشة يستخدم بروتوكول QFTV الموجود، مع التحقق من المحتوى ومكتبة محلية وفتح الوسائط المدعومة. دعم المتصفح للترميز لا يُضمن لكل ملف أو شاشة.
- حتى **3 ملفات، بإجمالي 512 MiB**. هذا حد قبول، وليس ضمانًا لكفاية الذاكرة على كل جهاز.
- ضغط، وتشفير اختياري AES-256-GCM، وتوقيع ECDSA P-256، وحذف بعد القراءة، وبروفايلات بث مخصصة. لا تُستبدل هذه الميزات بحالات شكلية.

## التشغيل

يلزم Node.js **22.13 أو أحدث**.

```sh
npm ci
npm run dev
```

بناء الإنتاج:

```sh
npm run build
npm run preview -- --port 3000
```

ينتج البناء `dist/` للويب ونسخة مطابقة في `www/` لـCapacitor. ملفات JavaScript/CSS وWASM والـworkers محلية، ويتولد `asset-manifest.json` من **كل** ناتج البناء، بما فيه الشاشات الكسولة.

## الأوفلاين والمشاركة

- **أُزيلت حزمة النشر ZIP وصفحتها ومدخل القائمة بالكامل.** تنزيل الملفات المستلمة معًا كـZIP ميزة مختلفة وما زالت موجودة.
- الويب/PWA يعمل أوفلاين بعد اكتمال أول تثبيت للكاش؛ مجرد ظهور الصفحة لأول مرة لا يكفي. يحتفظ Service Worker بالبناء السابق أيضًا لحماية التبويبات المفتوحة أثناء التحديث.
- APK يحتوي الأصول محليًا، ولا يعتمد على Service Worker أو اتصال بموقع الويب لعرض الواجهة والنقل البصري.
- مشاركة ملفات من تطبيق آخر إلى PWA المثبت تستخدم `POST /share` الذي يعالجه Service Worker **على الجهاز**. لا توجد نقطة رفع ملفات إلى خادم. فتح المسار مباشرة دون عامل نشط يعرض إرشادات، ولا يدّعي استيراد مشاركة.
- Android يستقبل `SEND` و`SEND_MULTIPLE`، ويقرأ Content URIs بمقاطع محدودة. حفظ الملفات يستخدم منتقي Android النظامي، بلا إذن تخزين عام.

## لغة الجهاز ومظهره

لا توجد مفاتيح لغة أو ثيم يدوية. الويب يستخدم أول لغة مدعومة في ترتيب تفضيلات المتصفح و`prefers-color-scheme`. Android يقرأ `Configuration` الفعلي ويستجيب لتغيره واستئناف التطبيق. ألوان Mulberry وGlisse تتبع هذه الإعدادات.

حركة Glisse وعدسة النص أصلية. مؤثر SVG لانكسار **الخلفية الحية** استُبدل بمادة ضبابية خفيفة بسبب كلفة التركيب المثبتة بالقياس؛ لم يُستبدل الشريط أو Menu بتقليد CSS.

## التحقق

```sh
npm run lint
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:release
```

`test:release` يولّد QR حقيقيًا للاختبارات ويشغّل تطبيق الإنتاج وخادم PeerJS محليًا. يشمل النقل والمحادثة، فك QR/RaptorQ، التشفير والتوقيع، الملفات الكبيرة، الأوفلاين البارد، Web Share، إلغاء الكاميرا، حدود تحديث الماسح، والتصميم والتنقل. تغذية الكاميرا بـcanvas **اختبار محاكاة** وليست تصويرًا بهاتف فعلي.

للاختبارات المستقلة للشاشات المعروضة، مع preview يعمل على 3000:

```sh
npm run test:routes
```

هذه اختبارات متصفح بعد تحميل React، وليست اختبارات SSR. تقارير التصاميم القديمة داخل `docs/*-evidence` أدلة تاريخية لإصداراتها، وليست اعتمادًا للإصدار الحالي.

## Android والنشر

راجع [DEPLOY.md](DEPLOY.md) و[docs/android-release.md](docs/android-release.md). إصدار Android يتحقق من اختبارات الويب وAndroid وتوقيع APK قبل دفع رقم الإصدار والوسم. لا ترفع رقم الإصدار يدويًا ثم تدفع إلى `main`؛ الـworkflow يرفع patch مرة واحدة.

تظل حدود الاختبار واضحة: نجاح متصفحين محليين أو Emulator لا يثبت أداء كاميرا فعلية، ولا كل إصدارات WebView، ولا الوصول عبر كل شبكات NAT/TURN. يجب إجراء قبول على الأجهزة المستهدفة قبل تعميم هذه الضمانات.
